## Уточнения и отклонённые способы исправления

**#2.** Воспроизведено преобразование native exit 7 в код PowerShell 1.
Это не означает, что исполнитель теряет любой явный код shell: `exit 7`
и запуск native-программы внутри PowerShell имеют разные контракты.
Первоначальный тест с ожидаемым 1 сам по себе не обосновывает выбранную семантику.
Принимается ясный контракт и проверка реальных сценариев; предложенная вставка
не принимается из-за устаревшего `$LASTEXITCODE` и изменения `$?`.

**#3.** Цикл с ожиданием 25 мс действительно вызывает проверку отмены на каждой
итерации; сама проверка перечисляет хранилище дважды. Частота «40 раз/с» —
верхняя оценка, а не измеренная нагрузка. Новый EventWaitHandle пока не нужен.
Не принимается безусловное игнорирование всех ошибок канала отмены: сначала
устраняется зависимость опроса от обслуживания всего хранилища. Срок, смерть
родителя и ресурсные ограничения сохраняются независимо от этого канала.

**#4.** Microsoft документирует требование FullControl у использованного
конструктора и возможность открытия с меньшими правами. Конкретный DACL
исторического объекта SYSTEM не сохранён; его состав из issue не является
наблюдённым фактом нашей машины. Не принимаются Everyone, неподтверждённый
диагноз старого отказа и произвольные retries на любой AccessDenied.
SYSTEM-контроль должен иметь подтверждённого владельца, срок и остановку;
обход общего исполнителя через новую неограниченную задачу не требуется.

**#5.** Искусственное состояние с двумя temp-файлами блокирует восстановление.
Однако последовательность его возникновения при нормальных обрывах ещё не
подтверждена: записи сериализованы одним mutex, а один остаток удаляется перед
следующей записью. Нельзя называть эту проверку воспроизведением причины OOM.
Неизвестные файлы, ссылки и нарушения общего бюджета сохраняют отдельный
порядок безопасного разбора. Не принимаются запуск без учёта результата,
`receipt_dropped` как общий обход квот и безусловное продолжение коллектора,
если его бюджет/путь/принадлежность не подтверждены. Простого try вокруг
`maintain` недостаточно: проверка runtime есть также в инициализации телеметрии.
Общий новый `repair`-интерфейс пока отложен; сначала нужны узкие правила
восстановления собственных файлов.

**#6.** Широкая allowlist на оболочку с произвольным payload опасна. Такая
allowlist в этой работе не устанавливалась. Точное поведение классификаторов
обоих клиентов и их UI не установлено из одной формы командной строки.
Читаемая форма помогает проверке человеком, но не доказывает сохранение
автоматической классификации вложенной команды. Декодированный исходник
не добавляется в квитанции, логи или долговременные previews.

**#8.** Private Bytes не описывает весь системный Commit. Но разность
`Committed − ΣPrivate − pools` — ориентир, не точный учёт shared sections
и не атрибуция виновника; нельзя включать `_Total` второй раз или игнорировать
валидность/время снимков. Рост Handle Count тоже не доказывает утечку секций.
Не принимаются точная «магическая» формула, отложенный запуск нового таймера
и обещание, что кольцевой сбор гарантированно продолжится при любом OOM.
Существующий BLG и времена событий остаются первыми источниками для разбора;
отсутствие incident-файла не означает отсутствие сбоя.

Первый пакет: лёгкая отмена и восстановление известных остатков (#3/#5),
безопасный отказ для многострочного cmd (#1), видимая обрезка и хвост (#7).

Следом: понятный контракт кодов (#2), incident-сегмент (#8), последовательная
читаемая форма (#6), небольшие исправления путей и heavy-классификации (#9).

Для каждого изменённого поведения нужна короткая проверка, сохраняющая лимиты,
очистку дерева, бюджет хранения и native approvals. Установка нового бинарника
и повторная клиентская приёмка — отдельный шаг после подготовки и проверки кода.
