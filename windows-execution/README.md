# Общий исполнитель Windows

v3 объединяет выполнение команд и hook-адаптеры Codex/Antigravity в одном
бинарнике. Исходники — четыре верхнеуровневых C# файла. Исторические v1/v2
сохранены в Git; `source-v1` — неизменённые исходники первоначального v1.
Текущий этап поставки указан в [записи GOAL](https://github.com/Kwentin3/codex/blob/main/docs/windows-execution/issue-review-2026-11-13.md).

## Выполнение команды

Внешняя оболочка — PowerShell. Рабочая папка задаётся штатным `workdir`/`Cwd`
инструмента. Весь полезный код находится внутри managed-команды:

```powershell
C:/Users/Администратор/.agents/windows-execution/agent-exec.v3.exe inline --owner TASK --shell powershell --timeout 60 --command-base64 ([Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes(@'
$ErrorActionPreference='Stop'
Get-Location
'@)))
```

Предпочтительна эта читаемая форма. Готовый UTF8 base64 допустим, когда литерал
не представляет исходник, например содержит сочетание `'@`. Отправляется
один точный вызов, без внешних `&`, переменных, комментариев и shell-операторов.
Максимум исходника — 16000 байт UTF-8. Примеры относятся к исходной установке
в профиле `Администратор`; для другой машины нужны её пути и нативная приёмка.

Для тяжёлой работы задаётся ASCII-owner `heavy:имя`; для намеренной фоновой —
`background:имя` или `background:heavy:имя`, явный срок и штатный async клиента.
Определение тяжести по словам внутри исходника удалено: `rg pytest` не занимает
heavy-слот только из-за текста поиска. Оболочки между вызовами независимы.
Многострочный `cmd` отклоняется до выполнения; для скриптов используется
PowerShell либо поддержанная оболочка bash.

```powershell
C:/Users/Администратор/.agents/windows-execution/agent-exec.v3.exe status
C:/Users/Администратор/.agents/windows-execution/agent-exec.v3.exe cancel 0123456789abcdef0123456789abcdef
```

После timeout/cancel/неизвестного результата проверяют конкретный RunId и
завершение дерева до повторного запуска. Массовое убийство по имени процесса
не является адресной остановкой.

## Результат и вывод

Квитанция сохраняет код **запущенной оболочки** или прямого native `exec`.
PowerShell-скрипт с последней неуспешной native-командой обычно заканчивается
кодом 1; для нужного исходного native-кода скрипт явно передаёт его:

```powershell
& $env:ComSpec /d /c exit 7
exit $LASTEXITCODE
```

Более ранний `$LASTEXITCODE` не используется для угадывания результата
произвольного многошагового скрипта. Явный `exit N` сохраняется. Внешний
PowerShell инструмента может показать 1 для любого ненулевого кода самого
исполнителя; точный код читается в квитанции и кратком служебном сообщении.
Код 125 может вернуть и исходная программа: `reason=exited` отличает этот
случай от служебного отказа, лимита или неподтверждённой очистки.

Начало и ограниченный хвост вывода сохраняются; обрезка явно помечается.
Stdout/stderr остаются в своих потоках. Голова, хвост, маркер и резерв
краткого служебного сообщения входят в общий лимит 64 КиБ. Для очень малых
тестовых лимитов используется сокращённый маркер. Полного файла вывода нет.
Запись служебного сообщения также ограничена по времени.

## Лимиты и наблюдение

Единственный владелец числовых настроек — `policy.json`: 2 ГиБ Commit и
32 процесса на дерево; четыре запуска, один heavy; очередь до 30 секунд;
явный срок до 1800 секунд. Проверка свободного системного Commit сохраняет
резерв максимальной группы плюс 4 ГиБ. Уменьшение до одного слота без атомарного
резервирования не применяется. Метрика берётся через `GetPerformanceInfo`.

Job Object получает suspended-процесс до первой инструкции, запрещает
breakaway и использует kill-on-close. Смерть родителя/владельца, timeout и
отмена завершают дерево. Отмена опрашивается раз в 500 мс без глобального
сканирования хранилища; timeout/родитель/лимиты проверяются отдельно.
У общих mutex явный DACL SYSTEM/Admin/оператор из policy, одинаковый при
создании пользователем и SYSTEM. ACL неизвестных существующих объектов
не переписывается, доступ Everyone не добавляется.

PerfMon/PLA снимает системную память и PID/Private Bytes/Handle Count каждые
15 секунд. Handle Count — косвенный сигнал, не доказательство утечки секций.
Активный BLG кольцевой 32 МиБ; видимый размер открытого файла может быть 0.
Свежесть подтверждается чтением закрытого BLG после штатной ротации.

В `D:\AgentExecutionDiagnostics`: active — резерв 64 МиБ, history/incidents —
384 МиБ, runtime — 32 МиБ, запас — 32 МиБ. Общий бюджет — 512 МиБ.
Обычные данные хранятся до 7 суток, инциденты до 30; квота может сократить срок.
Обслуживание при загрузке и каждые 15 минут; обе SYSTEM-задачи имеют TTL 2 минуты.
После Event 1003 и предыдущий, и следующий сегмент получают класс incident.
При нехватке памяти incident-задача может не стартовать: отсутствие отдельного
incident-файла не доказывает отсутствие сбоя. Разбор начинается с BLG и событий.

Известные собственные временные остатки восстанавливает RunStore. Телеметрия
использует его read-only структурный инспектор и не дублирует правила файлов.
Ошибка содержимого квитанций отображается как предупреждение и не останавливает
здоровый сбор, пока пути, принадлежность и бюджет подтверждены. Неизвестные
объекты, reparse и превышение физических границ сохраняют безопасный отказ.
Запуск без учёта результата и обход квот отсутствуют.

Root/runtime доступны только SYSTEM, администраторам и SID оператора.
Исходник команды существует временно в закрытом runtime; квитанции содержат
идентификаторы, контрольные суммы, результат и подтверждение очистки, без
исходника, окружения и полного вывода.

## Hooks и разрешения

Hook проверяет маршрут, не переписывает запрос и не выдаёт permissions.
AGY `decision=allow` передаёт управление следующему hook/default policy.
Широкую allowlist/auto-approve для `agent-exec ... inline` добавлять нельзя:
payload может содержать произвольные действия. Читаемая форма помогает человеку,
но не доказывает автоматическую классификацию вложенного исходника клиентом.

Codex требует review/trust точного определения hook; файл на диске не доказывает
активацию загруженного сеанса. У отключённого, непринятого или ошибочного hook
клиент может пропустить проверку; поведение ошибки/таймаута зависит от версии.
Служебные процессы IDE/MCP/browser имеют собственных владельцев. Новый локальный
запуск через другие tools требует проверенных штатных лимитов/остановки либо
общего исполнителя. Удалённая среда сохраняет своего владельца. Настоящий PTY,
постоянное состояние shell и модельный AGY headless не квалифицированы.

## Сборка, проверки и откат

Windows Server 2019 x64 / PowerShell 5.1, штатный .NET Framework csc, без NuGet:

```powershell
./build.ps1 -Name agent-exec.v3.exe
python ./tests/integration.py --binary ./agent-exec.v3.exe
```

Эти действия агента тоже выполняются внутри общего ограничителя. Сборка
не перезаписывает существующий versioned exe. Интеграция создаёт отдельные
policy/data_root и удаляет их; реальная клиентская приёмка проводится отдельно.
Хэши принятой сборки/исходников и результаты находятся в `snapshot.json`.
Совпадение хэша повторной компиляции не обещается; устанавливаются точные
байты проверенного артефакта. Исходный исторический v1 не пересобирается.

Для свежей установки готовят полный пакет и приватный `policy.json` из примера,
заполняют реальный storage_owner_sid, проверяют пути и выполняют `install.ps1`.
Скрипт сохраняет исходные глобальные файлы; существующие hooks и готовый rollback
требуют сохраняющего разбора, повторная установка поверх них отклоняется.

`rollback.ps1 -WhatIf` сверяет все исходные/установленные хэши. Реальный откат
останавливает только принадлежащие пакету collector/tasks и возвращает исходные
глобальные настройки, сохраняя диагностику. Все нативные владельцы проверяются
до первого stop/delete; повреждённый runtime не блокирует сам uninstall.
Нужны локальные rollback-файлы конкретной установки; приватные настройки,
базы, история чатов, сырые журналы и дампы в публичный Git не включены.
