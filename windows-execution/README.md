# Общий исполнитель Windows: снимок от 13.11.2026

Снимок принятой установки для Windows Server 2019 x64 / Windows PowerShell 5.1.
Он сохраняет исходники и результат расследования. Установка на другую машину
требует проверки путей, политики, версии клиента и нативного маршрута tools.

## Что где находится

| Файлы | Ответственность |
| --- | --- |
| `source-v1/*.cs` | Точные исходники принятого исполнителя и Codex-hook v1 |
| Верхнеуровневые `*.cs` | Исходники AGY-адаптера v2; содержит исправленный ответ `decision=allow` |
| `WinJob.cs` | Win32 Job Object, ограничения, остановка и проверка дерева |
| `RunStore.cs` | Временные запросы, состояния и ограниченные квитанции |
| `telemetry.ps1` | PerfMon/PLA, квоты, ротация, права доступа и архивы |
| `policy.example.json` | Числовая политика с незаполненным операторским SID |
| `hooks.*.json`, `install.ps1`, `rollback.ps1` | Шаблоны hooks, установка и адресный откат |
| `snapshot.json` | Хэши точных копий исходников и принятых локальных бинарников |

Все 20 файлов, перечисленных в `snapshot.json/files`, скопированы побайтово
из принятой установки. Пример политики и документация подготовлены отдельно.
Настоящий `policy.json` и пользовательские rollback-файлы сюда не копировались.

В коде и шаблонах сохранены строки пути профиля `Администратор`, относящиеся
к исходной установке. Это не универсальный установщик. Их изменение создаёт
нового кандидата, для которого прежняя приёмка нативных hooks недостаточна.

## Сборка

Требуется штатный .NET Framework compiler `Framework64/v4.0.30319/csc.exe`.
NuGet и внешние зависимости отсутствуют. Сборка не устанавливает hooks.

**Важна точная версия исходников.** Верхнеуровневый `build.ps1` собирает
верхнеуровневые C# файлы, то есть v2. Вызывать его нужно с явным именем:

```powershell
./build.ps1 -Name agent-exec.v2.exe
```

Для v1 используются четыре файла из `source-v1` и те же compiler flags:

```powershell
$compiler = Join-Path $env:SystemRoot 'Microsoft.NET/Framework64/v4.0.30319/csc.exe'
$output = Join-Path $PWD 'agent-exec.v1.exe'
if (Test-Path -LiteralPath $output) { throw 'Existing artifact must be preserved.' }
$sources = 'AgentExec.cs','ShellCommand.cs','RunStore.cs','WinJob.cs' |
    ForEach-Object { Join-Path $PWD ('source-v1/' + $_) }
& $compiler /nologo /langversion:5 /codepage:65001 /target:exe /platform:x64 /optimize+ /r:System.Web.Extensions.dll /r:System.Management.dll ('/out:' + $output) @sources
if ($LASTEXITCODE -ne 0) { throw 'Compilation failed.' }
```

Команды приведены для каталога `windows-execution`. Агент на исходной машине
помещает полезный код внутрь установленного managed-исполнителя по глобальной
политике. Не следует запускать новую неограниченную оболочку ради этих примеров.

Хэши локальных принятых exe записаны в снимке как идентичность установки.
Побайтовая воспроизводимость повторной сборки не доказана. Хэш компилятора v1
в момент его исторической сборки отдельно не подтверждён; это отражено в снимке.

## Политика и восстановление

По принятой политике: 2 ГиБ Commit / 32 процесса на дерево, четыре запуска
одновременно, один тяжёлый, явный срок до 1800 секунд, вывод до 64 КиБ.
Сбор памяти каждые 15 секунд; сроки хранения 7/30 суток, общий бюджет 512 МиБ.
Каталог диагностики закрыт для SYSTEM, администраторов и указанного оператора.

Для восстановления сначала готовят отдельную копию пакета, оба бинарника
из соответствующих исходников и `policy.json` на основе примера. Поле
`storage_owner_sid` заполняется реальным SID оператора. Проверяют пути hooks,
встроенного блока инструкций и доступ к каталогу диагностики. Затем отдельно
планируют установку, доверие hook и приёмку реального клиентского маршрута.
`install.ps1` сохраняет исходные глобальные файлы и не перезаписывает имеющиеся
hooks без сохраняющего слияния. Повторная установка поверх готового rollback
снимка намеренно отклоняется.

`rollback.ps1 -WhatIf` проверяет исходные и установленные контрольные суммы.
Реальный откат останавливает принадлежащие пакету collector/tasks и возвращает
точные исходные настройки, сохраняя диагностические данные. Для этого нужны
**локальные rollback-файлы конкретной установки**, которых нет в публичном Git.

## Проверки и границы

При исходной приёмке прошли 19 integration checks, 12 native lifecycle
behaviors, 34 проверки приватного хранения и 75 проверок архивирования.
Это результат первоначальной установки, а не новый прогон после клонирования.
Исходники проверок сохранены в `tests`. `RunStoreTests.cs` относится к более
раннему этапу до изменения общего mutex; его старый результат не переносится
на текущую версию. Старый `telemetry.tests.ps1`, создававший fixtures внутри
рабочего runtime, и одноразовые скрипты очистки в поддерживаемый снимок не включены.

Клонирование репозитория не запускает тесты и ничего не устанавливает.
Перед нативными тестами проверяют лимиты, изолированную директорию, способ
адресной остановки и текущую политику. `tests/agy-native-check.txt` содержит
малый ручной тест реального маршрута авторизованного AGY TUI.

Служебные процессы IDE/MCP/browser имеют собственных владельцев. Удалённые
процессы управляются удалённой средой. Отключённый, непринятый или пропущенный
клиентом hook не даёт гарантии контроля. PTY, постоянное состояние shell и
модельный headless-маршрут AGY не квалифицированы.

Подробности и открытые вопросы — в [описании инцидента](../docs/windows-execution/incident-2026-11-13.md).
